# AntiTrack

![Downloads](https://img.shields.io/github/downloads/CherretGit/zaprett-app/total)

Локальный блокировщик трекеров и рекламы для Android. Работает через собственный
VPN-сервис, который фильтрует DNS-запросы на устройстве: трафик приложений не
уходит на сторонние серверы, root не нужен.

Приложение показывает, сколько запросов заблокировано и какие приложения их
отправляли, умеет отдельно отключать блокировку трекеров и рекламы и проверять
обновления через GitHub Releases.

- Пакет: `ru.tapps.trackerblocker.stable`
- Минимальная версия Android: 7.0 (API 24)
- Текущая версия: 1.4
- Tracker list: <https://github.com/garte5484/alltrackerlist>
- Advert list: <https://github.com/garte5484/alladlist>

## Возможности

- **Блокировка трекеров и рекламы** на уровне DNS — без root и без проксирования
  всего трафика.
- **Два независимых списка** — трекеры и рекламные сети; блокировку каждого можно
  выключить отдельно в настройках. Блокировку трекеров можно отключить и для
  отдельного приложения в диалоге его статистики.
- **Живой лог DNS-запросов** — раздел «Логи» показывает домен, приложение, время
  и результат запроса: заблокирован трекер, реклама, заблокирован пользователем,
  троттлинг или запрос разрешён. Лог включается и выключается кнопкой наверху
  экрана; записи можно искать по хосту или приложению и фильтровать по результату
  (все / заблокированные / разрешённые). По тапу на запись открываются подробности
  (IP отправителя/резолвера, причина блокировки) с возможностью заблокировать
  конкретный хост (только его, без родительского домена) или разрешить ранее
  заблокированный хост.
- **Экран настроек** — блокировка трекеров и рекламы, выбор DNS-сервера,
  режим ответа на блокировку, доступ к статистике, резервное копирование,
  версия приложения и переходы к пользовательским правилам и блоклистам.
- **Управление блоклистами** — отдельный экран из настроек: для каждого списка
  видны число записей, размер кеша, время и источник обновления, его можно
  обновить отдельно или посмотреть содержимое с поиском. Автообновление
  отключается как для всех списков сразу, так и для каждого по отдельности;
  ручное обновление работает всегда.
- **Плитка быстрых настроек** — включение и выключение защиты одним тапом из
  шторки; плитка показывает состояние (включено, выключено, пауза, ожидание
  другого VPN) и умеет снять паузу.
- **Резервная копия** — экспорт и импорт настроек, пользовательских правил и
  исключённых приложений в JSON-файл через системный файловый диалог.
  Статистика и состояние защиты в копию не входят.
- **Пользовательские правила** — отдельный экран для ручной блокировки или
  разрешения хостов. Правило действует на домен и все его поддомены
  (`example.com` блокирует `ads.example.com` и `1.ads.example.com`), но не
  затрагивает соседние домены (`tracker.example.com`); более точное правило
  важнее общего. Разрешение отменяет блокировку из встроенных списков.
- **Статистика по приложениям** — сколько трекерных и рекламных запросов
  заблокировано, с разбивкой по брендам/доменам и фильтром по периоду
  («сегодня», «7 дней», «всё время»). Статистика сохраняется между
  запусками и сбрасывается одной кнопкой.
- **Автообновление списков** — при запуске скачиваются актуальные списки, если
  кеш старше 6 часов, а пока VPN работает, они проверяются раз в час.
  Автообновление можно выключить целиком или для отдельного списка, сохранив
  ручное обновление. Без сети используется последний сохранённый кеш, а при его
  отсутствии — небольшой встроенный набор.
- **Автозапуск после перезагрузки** — если защита была включена, VPN
  поднимается сам после старта устройства или обновления приложения. В
  настройках есть кнопки для разрешения автозапуска на ColorOS/MIUI/EMUI и
  для включения «Постоянной VPN» — она переживает перезагрузку даже там, где
  прошивка блокирует автозапуск сторонних приложений.
- **Возврат после другого VPN** — если вы временно включили другой VPN,
  AntiTrack остаётся в уведомлении и не отбирает у него слот, а защиту
  включает только после того, как чужой VPN будет отключён. Кнопка
  «Включить сейчас» в уведомлении возвращает блокировку немедленно.
- **Проверка обновлений приложения** через GitHub Releases: диалог с версией,
  прогресс скачивания, переход в системный установщик.
- **Выбор DNS-сервера** — по умолчанию используется системный DNS текущей
  сети; можно выбрать Яндекс.DNS, AdGuard, Cloudflare, Google, Quad9, OpenDNS
  или указать свой. Для зарубежных сервисов показывается предупреждение о
  доступности в России.
- **DNS over TLS** — разрешённые запросы можно шифровать (DoT) для выбранных
  провайдеров; при недоступности DoT автоматически используется UDP:53.
- **Защита от обхода через CNAME** — проверяется вся CNAME-цепочка ответа, а не
  только исходное имя запроса.
- **TTL-осведомлённый кеш** — ответы кешируются на время из DNS-ответа
  (30 секунд — 1 час), а не на фиксированные 2 минуты.
- **Настраиваемый ответ на блокировку** — NXDOMAIN (по умолчанию) или
  `0.0.0.0`/`::` для приложений, которые плохо переносят NXDOMAIN.
- **Уведомление о работе** — foreground-сервис с постоянным уведомлением и
  действиями: пауза блокировки на 15 минут, возобновление и остановка защиты.
- **Русскоязычный интерфейс** на Jetpack Compose / Material 3.

## Как это работает

AntiTrack поднимает локальный VPN и направляет в туннель **только виртуальный
DNS-сервер** (`10.88.88.53/32` и `fd00:1:fd00:1::53/128` для IPv6). Остальной
трафик — TCP и прочий UDP — Android отправляет в реальную сеть напрямую,
поэтому соединения не замедляются и не проксируются.

1. Приложение отправляет DNS-запрос, и он попадает в туннель AntiTrack.
2. Сервис разбирает имя запрашиваемого хоста и проверяет его по спискам:
   - домен или его поддомен есть в списке;
   - либо имя содержит ключевое слово из списка.
3. Если хост заблокирован, клиенту сразу возвращается `NXDOMAIN` (или нулевой
   адрес — по выбору пользователя), а факт записывается в статистику с указанием
   приложения.
4. Разрешённые запросы пересылаются выбранному DNS-резолверу — по умолчанию
   системному DNS текущей сети, при желании через DoT. Ответ кешируется на время
   из его TTL и возвращается клиенту.
5. Если в ответе есть CNAME-цепочка, её цели тоже проверяются по спискам:
   так ловится маскировка трекера под домен сайта.

Дополнительно:

- адреса известных DoH/DoT-резолверов (Cloudflare, Google, Quad9, AdGuard,
  NextDNS, ControlD, Mullvad, DNS0, CleanBrowsing и др.) уводятся в туннель,
  чтобы приложения не обходили фильтр через зашифрованный DNS;
- при всплеске трекерных запросов (больше 2 за 10 секунд) приложение на 3 секунды
  теряет доступ к DNS — это снижает активность фонового трекинга;
- авторы запросов определяются через `ConnectivityManager.getConnectionOwnerUid`
  (Android 10+) либо через `NetworkStatsManager`. Для точной статистики нужно
  разрешение «Доступ к использованию приложений»; без него запросы могут
  записываться в «Систему».

VPN не пропускает через себя пользовательский трафик и не использует внешние
серверы. Наружу уходят только:

- запросы за списками блокировки (GitHub Raw);
- DNS-запросы разрешённых доменов к выбранному резолверу (по умолчанию —
  системному DNS сети; можно выбрать Яндекс.DNS, AdGuard, Cloudflare и др.);
- проверка обновлений и скачивание APK (GitHub).

## Требования

- Android 7.0 (API 24) или новее.
- Разрешение на создание VPN-подключения (запрашивается при первом включении).
- Разрешение на уведомления на Android 13+ (для foreground-сервиса).
- Опционально: «Доступ к использованию приложений» — для точной статистики по
  приложениям.
- Свободный слот VPN: одновременно может быть активен только один VPN.

## Установка

1. Скачайте APK из [раздела релизов](https://github.com/garte5484/antitrack/releases).
2. Разрешите установку из неизвестных источников, если система попросит.
3. Откройте приложение и нажмите «Включить защиту», подтвердите создание
   VPN-подключения.

> Если ранее была установлена debug-сборка, её нужно удалить: release-версия
> подписана другим ключом, и Android не позволит обновить приложение поверх неё.
> Настройки и статистика при удалении будут потеряны.

## Сборка из исходников

### Что понадобится

- JDK 25 (версия Gradle daemon зафиксирована в
  `gradle/gradle-daemon-jvm.properties`);
- Android SDK с установленным API 37 (`compileSdk = 37`);
- Gradle и зависимости скачиваются автоматически через wrapper.

### Debug-сборка

```bash
./gradlew :app:assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`

### Release-сборка

Release подписывается ключом, параметры которого читаются из файла
`keystore.properties` в корне проекта:

```properties
storeFile=keystore/antitrack-release.jks
storePassword=ваш_пароль
keyAlias=antitrack
keyPassword=ваш_пароль
```

Сам ключ и `keystore.properties` исключены из git. Без этого файла release
соберётся неподписанным.

```bash
./gradlew :app:assembleRelease
```

Готовый APK: `app/build/outputs/apk/release/app-release.apk`

> **Важно:** сохраните keystore и пароль в надёжном месте. Потеря ключа означает,
> что обновить уже установленное приложение будет невозможно — придётся удалять
> его и устанавливать заново.

### Тесты

```bash
./gradlew :app:testDebugUnitTest
```

Покрыто сравнение версий для автообновления (`UpdateCheckerTest`), разбор
списков и DNS-пакетов, ручные правила (`HostRulesTest`: домен и поддомены,
приоритет более точного правила) и определение брендов.

## Выпуск обновлений

1. Поднимите `versionCode` и `versionName` в `app/build.gradle.kts`.
2. Соберите подписанный release APK.
3. На GitHub создайте релиз с тегом, например `v1.1` (или `1.1`), и прикрепите к
   нему `app-release.apk`.
4. Опубликуйте релиз.

Приложение при запуске запрашивает последний релиз через GitHub API, сравнивает
версию из тега с установленной и, если она новее и в релизе есть `.apk`, предлагает
обновление. Версии сравниваются по числовым компонентам: `1.2.10` новее `1.2.9`,
`v2.0` новее `1.9.9`. Суффиксы вроде `-beta` игнорируются после числовой части.
Учитываются только опубликованные релизы: черновики и pre-release не видны
проверке.

Скачанный APK сохраняется во внутреннюю папку `filesDir/updates` и передаётся
системному установщику через `FileProvider`. Если установка из этого источника
запрещена, приложение откроет соответствующий экран настроек.

## Источники списков

| Список | URL |
| --- | --- |
| Трекеры | <https://raw.githubusercontent.com/garte5484/alltrackerlist/refs/heads/main/simple/lite> |
| Реклама | <https://raw.githubusercontent.com/garte5484/alladlist/refs/heads/main/simple/lite> |

Поддерживаются несколько форматов строк:

- `domain.com` — блокируется домен и все его поддомены;
- `0.0.0.0 domain.com` — hosts-формат;
- `||domain.com^` — AdBlock-синтаксис;
- `keyword` (без точки) — блокируется любой хост, содержащий это слово.

Комментарии (`#`) и пустые строки игнорируются. Кеш обновляется раз в 6 часов;
при ошибке загрузки используется предыдущая версия списка.

## Приватность

- Нет аккаунтов, рекламы, телеметрии и сторонней аналитики.
- Статистика блокировок и настройки хранятся только на устройстве
  (`SharedPreferences`).
- Трафик приложений не проксируется и не передаётся третьим лицам.
- Разрешённые DNS-запросы пересылаются публичным резолверам — они видят
  запрашиваемые домены, как и при обычном использовании DNS.
- Заблокированные домены никуда не отправляются: ответ формируется локально.

## Ограничения

- Фильтрация работает на уровне DNS. Соединения по IP, SNI и трафик приложений,
  использующих собственный зашифрованный DNS с неизвестным адресом, могут не
  блокироваться.
- Точность статистики по приложениям зависит от версии Android и выданного
  разрешения «Доступ к использованию приложений».
- Одновременно с AntiTrack нельзя использовать другой VPN: при его запуске
  защита приостанавливается, а после отключения чужого VPN включается снова.
- Приложение не является межсетевым экраном и не блокирует рекламу, встроенную
  в офлайн-контент или загружаемую с тех же доменов, что и полезные данные.

## Структура проекта

```
app/src/main/java/ru/tapps/trackerblocker/stable/
├── MainActivity.kt          # UI на Compose, настройки, диалоги обновления
├── BlockVpnService.kt       # VPN-сервис: DNS-фильтрация, кеш, статистика, троттлинг
├── DnsParser.kt             # Разбор DNS-пакетов
├── BlocklistRepository.kt   # Загрузка и кеширование списков
├── TrackerBlocklist.kt      # Сопоставление с трекерами
├── AdBlocklist.kt           # Сопоставление с рекламой
├── BlockStats.kt            # Статистика по приложениям и доменам
├── BrandNames.kt            # Названия брендов и иконки
├── DomainLabeler.kt         # Определение бренда по домену
├── UpdateChecker.kt         # GitHub Releases: проверка и скачивание APK
├── AppSettings.kt           # Переключатели блокировки
├── HostRules.kt            # Пользовательские правила (домен + поддомены)
├── SettingsBackup.kt      # Экспорт и импорт настроек и правил
├── QuickTileService.kt    # Плитка быстрых настроек
├── RussianPlural.kt         # Склонение числительных
└── ui/theme/                # Цвета, типографика, тема Material 3
```

Основные ресурсы: `app/src/main/res/values/strings.xml` (русские строки),
`app/src/main/AndroidManifest.xml` (разрешения и сервисы),
`app/src/main/res/xml/file_paths.xml` (доступ FileProvider к скачанному APK).
